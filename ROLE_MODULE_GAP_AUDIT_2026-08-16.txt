AWIBI EHR — ROLE, DIAGNOSTICS, PHARMACY, RECORDS, EQUIPMENT AND PROVENANCE AUDIT
Date: 16 August 2026
Status vocabulary: [x] implemented and evidenced; [~] partial; [ ] not built / release work

DECISIONS THAT MUST NOT DRIFT

[x] 01. Patient registration and demographic correction belong to Records/Reception and authorised facility administrators.
[x] 02. Doctors, nurses and pharmacists may find/read patient records only within their care role; patient access does not make registration a doctor function.
[x] 03. The API protects registration with patient_demographics_write.
[x] 04. The UI now hides Register Patient from roles without patient_demographics_write.
[x] 05. The /patients/add route now requires patient_demographics_write, not generic patient read access.
[x] 06. Shared patient access is now labelled Patient Access in navigation instead of placing registration under Clinical.
[x] 07. Doctors own consultation, diagnosis, prescriptions and diagnostic/nursing orders within scope.
[x] 08. Diagnostics staff process assigned investigations; they do not originate the doctor's clinical order.
[x] 09. Pharmacists must verify/dispense/recommend without silently rewriting a signed prescription.
[x] 10. Admin owns configuration and oversight; being facility owner does not automatically grant clinical authorship.

AUTOMATIC PROFESSIONAL / DATE / TIME PROVENANCE

[x] 11. Consultation author is taken from the authenticated user; the browser cannot supply another author.
[x] 12. Consultation EHR recorded time is immutable server createdAt.
[~] 13. Consultation clinical occurrence time defaults to server now; code/build complete, local database migration and live E2E pending.
[~] 14. A clinician may select an earlier care time for retrospective documentation; code/build complete, local database migration and live E2E pending.
[~] 15. A retrospective consultation requires a late-entry reason; code/build complete, local database migration and live E2E pending.
[~] 16. Future consultation times are rejected by the API; code complete, local runtime evidence pending.
[~] 17. Care time, EHR record time, author, reviewer and signer remain distinct facts; local database migration pending.
[x] 18. Monitoring-chart creator and EHR creation time are automatic.
[~] 19. Monitoring start time defaults to server now or accepts an explicitly justified earlier time; local database migration pending.
[x] 20. Each observation recorder and immutable EHR createdAt are automatic.
[~] 21. Observation time defaults to server now or accepts an explicitly justified earlier time; local database migration pending.
[~] 22. Future monitoring/observation times are rejected; code complete, local runtime evidence pending.
[~] 23. Late entries are visibly labelled with occurrence time, EHR time and reason; frontend production build passes, live E2E pending.
[x] 24. Signed consultations remain immutable; corrections use an amendment rather than overwriting history.

DIAGNOSTICS — CURRENTLY WORKING

[x] 25. One catalogue covers laboratory, imaging, ECG and other diagnostic requests.
[x] 26. New Encounter and standalone ordering both require an active facility catalogue item.
[x] 27. Orders snapshot unit, reference range, discipline, specimen and patient demographic context.
[x] 28. Doctor ordering and diagnostics processing are separated by RBAC.
[x] 29. Specialist roles exist for radiology, radiography, haematology, chemical pathology, histopathology/morbid anatomy and microbiology.
[x] 30. Specialist queues are filtered by modality/discipline.
[x] 31. Laboratory specimen flow and imaging/non-specimen flow use different valid transitions.
[x] 32. Preliminary, final and corrected reports retain version/provenance.
[x] 33. Critical results open a persistent acknowledged/acted-on/resolved lifecycle.
[x] 34. Final consented results can be released to the linked Awibi Identity inbox.
